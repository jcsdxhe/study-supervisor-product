# 架构说明

## 架构目标

- 基础学习管理在无账号、无网络、无 API Key 时可用；外部 AI 只做渐进增强。
- 用户学习数据默认留在浏览器本机，媒体和模型请求必须由用户显式触发。
- UI、状态、持久化、外部服务与模型协议校验保持边界，失败必须可见且可恢复。
- 不执行模型返回代码；AI 只能通过经过白名单、类型、长度、数量和坐标范围校验的结构化事件提出动作。

## 运行结构

```text
Edge / Chrome
  ├─ 学习计划、计时、成绩、复盘       → localStorage
  ├─ 证据、图片、PDF 页、白板批注      → IndexedDB
  ├─ 课堂文字档案与本地视频回放        → 独立 IndexedDB
  ├─ 摄像头/麦克风/屏幕               → 用户点击后浏览器权限
  └─ AI 请求                          → 默认 127.0.0.1 Node 代理
                                       或同源 HTTPS 安全云代理（显式授权后）
                                          └─ Kimi API（仅用户主动请求）
```

## 前后端分层

| 层次 | 组成 | 依赖边界 |
|---|---|---|
| 展示与交互 | `index.html`、各 CSS 文件 | 负责语义结构、响应式布局、权限入口与状态反馈 |
| 浏览器领域模块 | `app.js`、`daily-report.ts`、`supervision.js`、`whiteboard.js`、`kimi.js`、`voice-class.js` | 编排学习、日报、监督、白板和课堂行为，不读取服务端密钥 |
| 浏览器适配器 | localStorage、IndexedDB、Canvas、SpeechRecognition、speechSynthesis、MediaDevices | 封装持久化、绘图、语音和显式媒体权限 |
| 安全代理 | `server.js` | 默认提供本机静态资源与 Kimi 代理；云模式额外提供口令登录、签名 Cookie、来源校验、安全响应头和健康检查 |
| 外部服务 | Kimi Chat Completions | 仅接收用户主动发送的题图或最终文字，不直接访问 DOM 或本地数据 |

依赖方向保持为“展示 → 领域模块 → 浏览器/本机服务适配器”。外部服务只能返回待验证数据，不能直接控制页面、画布或持久化内容。

## 本地数据模型

| 存储 | 内容 | 生命周期与恢复 |
|---|---|---|
| `localStorage` | 计划、任务、计时、成绩、复盘、专注设置、个人资料、导航偏好、一次课堂方案，以及版本化的动态目标与日报 | 学习状态继续使用 `forward-study-v1`；个人资料使用 `study-supervisor-profile-v1`；导航和课堂方案分别使用 `forward-nav-state-v1`、`forward-classroom-blueprint-v1`；这些新增偏好不修改旧结构；现有“数据”导出暂不包含个人资料、日报与附件 |
| `IndexedDB` | 统一证据中心附件、导入题图、PDF 栅格页、白板页面与批注历史 | `forward-evidence` 升级为版本 `2`，保留旧 `files` 记录并增加 `reportDate`、`goalId` 索引；发行包不携带实例数据 |
| `forward-classroom` IndexedDB | `sessions` 记录使用数据版本 `2`：在既有起止时间、题目转写、师生文字、复盘上新增教学模式与事件时间轴；`recordings` 保存 WebM/MP4 Blob | 数据库仍为版本 `1`、store 不变；旧 session 没有 `events` 时由完整文字记录生成只读时间轴，不需要破坏性迁移；删除课堂时事务式删除关联录屏 |
| `forward-learning-library` IndexedDB | 版本 `1` 的 PDF、图片和文字资料 Blob、页数、大小与名称 | 独立于白板和课堂；单文件 40 MB，PDF 最多 10 页；删除资料不级联删除已经生成的白板页或课堂档案 |
| 服务端内存 | Kimi 会话、一次性能力凭证、请求计数和语音课堂上下文 | Node 进程结束即清除，不作为用户数据备份 |
| `.env` | Kimi 密钥与本机限额配置 | 仅由本机 Node 进程读取，不进入浏览器存储、日志、导出或发行包 |

日报模块新增独立的版本化 localStorage 结构，并将既有证据库从版本 `1` 原位升级到 `2`。升级只添加索引，不删除或改写旧附件；旧记录缺少关联字段时按“未关联目标”显示。若日报 JSON 损坏，模块回退为空结构且不覆盖证据库。完整附件备份/恢复尚未实现，删除证据前必须二次确认。

任务和成绩的编辑/删除沿用既有 `forward-study-v1` 数组结构，没有数据迁移；旧记录原位兼容。个人管理采用独立 `study-supervisor-profile-v1`，损坏或未知版本会回退到默认资料而不覆盖学习状态。白板右键删除复用既有 IndexedDB 页面删除事务，不改变数据库版本；删除前必须确认，删除页面及其批注后不可撤销。

### 1.7.2 课后任务来源

`forward-study-v1.tasks[]` 增加可选 `source`：`{ version: 1, type: "classroom-homework", sessionId, homeworkId, question }`。字符串长度分别限制为 100、30、1800；未知版本或无效字段不显示来源入口。同一课堂、作业 ID 与题目内容共同去重，避免复盘重新生成并复用作业 ID 时隐藏新题。任务标题、说明、完成状态或星期修改不影响来源。

这是兼容旧记录的附加字段，不升级 localStorage 键或 IndexedDB 版本，不改写历史任务。新建任务仅在 localStorage 保存成功后进入内存和界面；失败保留原状态并允许重试。删除任务后可重新添加；删除课堂不会级联删除任务，来源入口显示缺失提示。现有 JSON 任务备份包含来源字段，但不包含课堂 IndexedDB；只恢复任务时仍可能找不到原课堂。旧版本若不识别来源字段，任务正文仍可使用。

## 日报分析器扩展边界

`DailyReportAnalyzer` 是模型无关的 TypeScript 接口。提供方通过 `window.DailyReportAI.register()` 注册，只能在未来的显式用户操作中收到只读日报、目标和证据元数据；首版没有注册任何实现，也没有网络请求。后续接入 OpenAI、Claude、Kimi 或本地模型时，密钥仍须留在本机服务端环境变量，响应必须先经过结构、长度和数量校验，失败与取消必须可见且可恢复。

## AI 请求边界

```text
用户确认发送
  → 浏览器生成当前画布/选区与最终问题文字
  → 默认 127.0.0.1 Node 代理，或已解锁的同源 HTTPS 云代理
  → 代理校验认证、来源、大小、模型、限额和会话
  → Kimi Chat Completions
  → 服务端解析并校验 JSON / JSONL / SSE
  → 浏览器显示回答；批注事件经用户确认或课堂授权后进入白板 action
```

密钥永不下发浏览器。网络错误、超时、限额和协议错误都必须返回明确状态；不得用未校验文本直接改动白板。能力自检现在用于显示不确定性而不拦截难题：低清晰度、低信心和高图像依赖仍继续调用 Kimi，但提示词要求标出不确定字符、进行条件式分析并禁止虚构题干或跳转其他 AI。

## 语音课堂协议

1. `/api/kimi/voice/start` 接收当前题图一次，得到题目转写、知识点和归一化区域 anchors。
2. `/api/kimi/voice/turn` 接收后续最终问题文字；仅在用户主动课堂批注并确认发送时附带当前批注页，然后流式解析 JSONL：
   - `say`：适合朗读的一至两句话；
   - `mark`：引用 anchor，在原题图上画 highlight/circle/rect/arrow；
   - `board`：将公式或推导写到板书页；
   - `plot`：经服务端与浏览器双重校验的白名单函数图；
   - `motion`：经双重校验的 `kinematics`、`projectile` 或 `incline` 物理动画。
3. 浏览器将 `say` 送入 speechSynthesis，将画布事件交给 `LocalWhiteboard`。提示协议要求 `mark`、`board`、`plot` 或 `motion` 先于解释它的 `say`；客户端把当时的页面 ID 写入朗读队列，并在句子真正开始朗读时切换页面。`motion` 页面由本地确定性播放器提供播放、暂停、拖动和从头重播，切页时暂停，不会重新请求模型。
4. `board` 事件只接受有序文字与颜色，忽略模型坐标；`LocalWhiteboard.applyTeachingBoard` 负责换行、行高、游标和自动续页，确保新增板书矩形互不重叠。
5. 课堂页面浏览器只保存本次前端会话中的页面引用和预览，实际原题、板书与教学图仍复用 IndexedDB 白板页。用户点击缩略图后进入手动回看状态，后续事件只更新页面列表而不抢屏；恢复自动跟随后才切到最新讲解页。物理教学页新增可选 `animationSpec` 字段，保存已通过白名单校验的动画参数；播放器状态只驻留当前页面会话。该字段是向后兼容的附加字段，不升级 IndexedDB 版本；旧记录没有该字段时继续显示静态最终帧。
6. 模型输出先经服务端类型、颜色、数量、范围和长度约束；网页不执行模型代码。服务端记录完成原因、无效 JSONL 行和视觉事件数；长度截断、协议全失效和明确画图却无图分别返回可见错误或警告。浏览器对连续 45 秒无新内容的请求主动中止并提供重试。
7. 课堂个人批注沿用现有白板 action，标记为 `classroom-user`；只允许画笔、圆圈和箭头，撤销只删除当前页最近一条个人批注。批注页以一次性请求图片传入，不进入服务端历史，因此下一轮不会隐式重复上传。
8. `classroom-archive.js` 在课堂开始时建立版本化本地 session，并在用户确认发送、教师回答实际完成时追加文字记录。结束课堂写入结束时间并打开详情；课堂启动失败时丢弃空档案。
9. `/api/kimi/voice/review` 是显式、无状态的课后请求：只接收当前课堂题目转写、有限长度的文字记录和用户选择项。服务端校验输入总量，用 `review-protocol.js` 清洗总结、作业及答案映射后返回；录屏永不进入该接口。
10. 一键课堂方案只把用户主动填写的主题、目标、难度、场景与角色作为有限课堂上下文传给后续文字轮次；角色是同一个模型的教学职责，不伪装成多个独立实时模型。上下文最多保留 6000 字符且仅驻留 Node 进程内存。

语音识别和提交是两个状态：SpeechRecognition 可连续产生临时/最终片段，但默认只更新可编辑输入框；用户确认后才调用 `/voice/turn`。可选自动提交使用 2.2 秒本地防抖。老师朗读、模型请求和页面后台状态都会停止识别；麦克风屏蔽是默认状态，“打断老师”只取消 SSE/朗读，不会隐式打开麦克风。

课堂录屏使用用户手势触发的 `getDisplayMedia` 和 `MediaRecorder`。用户在浏览器原生面板选择共享目标及是否包含标签页/系统声音；应用不自动附加麦克风轨道。录制按块缓冲，停止后保存为 IndexedDB Blob；配额失败可见，页面结束时停止所有共享轨道。回放使用临时 Blob URL，并在切换或关闭详情时撤销。浏览器不支持、用户拒绝、共享轨道被撤销时，文字课堂仍可继续。

录制中的暂停/继续直接使用 `MediaRecorder.pause()` / `resume()`，不会重新请求权限或创建第二段文件。课堂时间轴仅保存录屏状态事件和课堂页面 ID，不复制大体积图片或视频；白板页被用户删除后，时间轴会保留文字证据并显示页面不可用。

## 可安装 Web App 边界

`manifest.webmanifest`、`pwa.js` 与 `sw.js` 提供渐进式安装和基础离线壳。Service Worker 仅处理同源 GET 静态资源，显式绕过 `/api/`、POST 和跨源请求；因此不会持久化 Kimi 会话、题图请求或回答。PWA 不改变 localStorage/IndexedDB 数据模型。

响应式外壳把导航行为分为三档：手机（≤760px）为带遮罩、焦点回收、Esc 关闭和左右滑动手势的抽屉，并提供底部快捷栏；平板（761–1100px）默认为紧凑图标侧栏；电脑为可收起侧栏。课堂在手机上以“讲义/对话”单面板切换，避免两列内容被纵向堆成超长页面。导航偏好只存本机，不进入课堂或 AI 请求。

Node 服务默认仍只监听 `127.0.0.1`。仅当 `ALLOW_CLOUD_PROXY=true` 且 Kimi Key、访问口令、签名密钥和 HTTPS Origin 全部有效时才监听 `0.0.0.0`。云模式的访问口令不进入 Cookie；服务签发 1–72 小时的 HMAC 会话 Cookie，默认 12 小时。学习数据模型没有变化，云端不新增数据库。

云模式静态网页可以公开加载，但所有 Kimi API 在认证前返回 401。登录和 API POST 必须来自部署 Origin；错误登录按转发来源窗口限速。容器构建采用白名单 COPY 与白名单 `.dockerignore`，不把 `.env`、测试产物或用户文件发送进镜像上下文。

## 数学绘图与物理动画边界

当前未发布分支已实现受控 `plot` 事件：函数表达式由本机 tokenizer/AST 求值器解析，并按字符、token、节点、曲线、采样和坐标跨度限制后用 Canvas 绘制；不允许返回或执行 JavaScript。当前协议示例：

```json
{
  "type": "function_plot",
  "expressions": [{"source": "exp(x*x)*sin(x)", "color": "#2979ff"}],
  "domain": [-2, 2],
  "range": [-4, 4],
  "fill": {"from": 0, "to": 2, "between": [0, 1]}
}
```

物理 `motion` 允许匀加速直线、抛体、斜面和 `collision_1d`。碰撞协议只接受 2–6 个物体、有限质量/速度/半径、有限世界边界和 0–1 恢复系数；客户端以固定时间步确定性求解，并显示总动量与总动能。模型只能返回参数，不能返回或执行代码。几何图、受力图自由编排、参数方程、隐函数和三维图仍属于后续扩展。

扩展验收至少覆盖：非法表达式拒绝、节点/采样/时间预算、奇点与非有限值、坐标范围裁剪、确定性渲染、撤销重做、导出以及 headed Edge/Chromium 视觉回归。引入第三方绘图库前还需评估许可证、包体积、维护状态和离线发行影响。

## 通用扩展方式

- 新学习模块：隔离状态、规则与渲染；为持久化键定义版本，并覆盖导入、导出、迁移和损坏恢复。
- 新白板工具：实现统一 action 的创建、渲染、撤销、重做、序列化和导出，不绕过历史栈直接修改画布。
- 新 AI 事件：先定义 JSON Schema、白名单、数量/长度/坐标预算和拒绝策略，再实现服务端验证与前端渲染。
- 新模型供应商：保持浏览器协议稳定，在 Node 侧增加 provider adapter；密钥继续只来自服务端环境变量。
- 新浏览器能力：采用渐进增强，必须覆盖不支持、权限拒绝、权限撤销和中途失败时的基础回退。
- 新依赖：先评估必要性、许可证、维护状态、体积、离线可用性和发行影响，再纳入构建与安全检查。
